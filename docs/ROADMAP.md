## 1. 已完成

**工程与基础设施**
- 主控状态机 `scripts/core/main.gd`：TITLE / HUB / RUN / GAMEOVER 四态 + 内置七个自检入口。
- 全局单例：`Events`（事件总线）、`Game`（元进度 / 存档 / 难度 / 打击停顿）、`Sfx`（程序化合成的 40+ 音效，零外部素材）。
- `RunState`：资源、词条汇总 `recalc()`、六种铳械模块、污染值、结算规则。
- `UpgradeDB`：55+ 条局内词条 + 六种铳械模块，稀有度权重与按层解锁。
- `UITheme`：配色 + **系统中文字体运行时挂载**（Godot 默认字体不含 CJK，必须走这条路）。

**战斗**
- 玩家：移动 / 二段跳 / 冲刺 / 剑三段连击 / 蓄力重斩 / 格挡与完美格挡（0.22s）/ 盾击 / 铳与热量 / 幽灵形态 / Q 探测回波。
- `EnemyDB`：设定文档表 8-1 的 **21 种敌人** 全部建档，五类克制（机械怕电磁、人形怕中毒、异常生物怕灼烧、智能体怕骇入、幽灵体需先探测）。
- `Enemy`：七态行为机（含炮塔 / 飞行 / 蜂群 / 精英），姿态（Poise）与硬直、击退、精英减伤。
- 具名 Boss：三层各一个（B1 织网铆接体 / B2 中枢塞勒 / B3 霍尔斯特），共用精英单位放大 + 独立配色 + 专属血条。
- 弹道、命中停顿、屏幕震动、伤害数字、残影、火花、光环、拾取物与磁吸。

**肉鸽循环**
- `Level` 程序化扇区：房间序列（START / COMBAT / ELITE / REWARD / SHOP / REST / BOSS）+ 三层平台 + 闸门 + 五套主题配色。
- 房间清空 → 数据舱三选一 → 写回 `RunState` → 开门推进；精英房与 Boss 房额外掉落。
- 据点元进度：9 项永久升级（碎片结算）、黑市（盲区币预购，下一局生效）、长椅、离线终端（记忆残页）。

## 3. 关键技术决策

| 决策 | 理由 |
|---|---|
| Godot 4.7.2（`C:\Godot\Godot_v4.7.2-stable_mono_win64\`） | 本机已装；纯 GDScript，不需要 .NET SDK |
| 全代码构建场景，几乎不用 `.tscn` | 手写场景文件易错且不可 diff；代码生成可控、可用 headless 校验 |
| 零外部素材：绘制用 `_draw()`，音效用 `AudioStreamWAV` 合成 | 无美术资源也能先验证手感与循环；仓库里没有二进制资源 |
| 运行时注册输入映射（`InputActions`） | 避免 `project.godot` 里的 InputEvent 序列化文本，且天然支持改键 |
| 碰撞查询用手动 `intersect_shape` / `intersect_ray`，不铺 Area2D | 节点数少、命中逻辑集中、易调 |
| 中文字体运行时从系统加载 | Godot 默认字体无 CJK 字形，会显示为方块 |
| 无头自检一律带 `--quit-after` | 部分流程的退出路径会悬住，不加帧上限时进程可能不退出 |
| 新增 `class_name` 脚本后必须跑 `--import` | 否则全局类名缓存缺失，会报 `Could not find type "..."` |

## 4. 自检与验证

工程内置七个可命令行调用的自检（`--selfcheck` / `--combatcheck` / `--mapcheck` /
`--bosscheck` / `--elementcheck` / `--servicecheck` / `--shot`），用法见 `README.md`。

**headless 自检覆盖不到任何 `_draw()`**，所以纯视觉问题只能靠 `--shot` 截图肉眼查。
每次改完画面相关代码，跑一次 `--shot` 再看图。
